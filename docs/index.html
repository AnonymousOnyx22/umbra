Categorized

read, search, list, edit, run, context — each with its own color, the target it touched, and a one-line result.

Folded by default

Twelve reads in a row become one read · 12 files line. Click any row, or ctrl+e for everything.

Timed, live

A blinking ghost and a clock hold the space while the model thinks, so a slow local model never looks hung. Rows spin while they run; esc stops a turn.

Copyable

Drag to select and ctrl+c, right-click a row to copy it whole, or f12 to hand the mouse back to your terminal.

#bring your own models

Anything Ollama can run, umbra can drive — including models you built or imported yourself.

# pull one from the registry, without leaving umbra
/pull qwen2.5-coder:14b

# or import your own GGUF and use it the same way
echo "FROM ./my-finetune.Q5_K_M.gguf" > Modelfile
ollama create my-coder -f Modelfile
umbra --model my-coder

# f2 switches between everything `ollama list` reports

No keys, no account

There is no cloud API behind this. Nothing is billed, nothing is rate-limited, and a session costs exactly $0.00.

Nothing leaves the box

By default, your code goes to Ollama at 127.0.0.1:11434. You can also choose another host with --host.

Works with small models

Models without function-calling get an XML tool protocol instead, so 7B coders work out of the box.

#install

Install Ollama first, then pull the model you want to run.

  1. Get a model

    ollama pull huihui_ai/qwen2.5-coder-abliterate:7b

  2. Install umbra

    git clone https://github.com/AnonymousOnyx22/umbra
cd umbra
pip install -e .

  3. Run it in any project

    cd ~/code/my-project
umbra

  4. Optional — put it in the Windows Start menu

    powershell -ExecutionPolicy Bypass -File tools\install_shortcut.ps1

#two agents

tab switches between them, and the composer always says which one is live.

Build

Reads, searches, edits files and runs commands. Every edit is a unified diff you approve — unless you've told it not to ask.

Plan

Read-only. It investigates and writes you a plan; edits and shell commands are refused at the tool layer, not just discouraged in the prompt.

On /yolo: for this session, it removes edit and command confirmations and lifts the git requirement. Model-generated deletion commands remain blocked. Overwritten files are copied to ~/.umbra/backups first, /undo puts the last one back, and every edit and command is appended to ~/.umbra/audit.log. Worth knowing before you turn it on.
